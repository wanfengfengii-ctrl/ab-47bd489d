# 封闭展柜氮气风道 · 整数流量认证

换气前，保管员在此编辑**节点净注入量**与**有向风道**（方向、整数流量上下限），
系统认证氮气能否沿风道送达每个展柜并从排放口带走，不留失去保护气氛的角落。

- 可行：展示**逐风道整数流量**，并逐节点复核收支守恒。
- 不可行：给出**导致缺口的节点集合**与**最小未满足流量**，标明是哪片库房无法平衡。

## 认证同时裁决的三个条件

1. **全网净注入平衡**：所有节点净注入量之和为 0（源注入 = 排放口排出）。
2. **节点收支守恒**：对每个节点 `流出 − 流入 = 净注入量`。
3. **风道容量区间**：对每条风道 `下限 ≤ 流量 ≤ 上限`（整数，**正下限风道同样参与整体裁决**）。

求解方法：带下界的可行循环变换（令 f = lower + x）+ Dinic 最大流，
整数容量保证整数解；不可行时由最大流最小割给出缺口见证。

## 本地开发

```bash
npm install --cache .npm-cache   # 如 npm 缓存目录权限受限时
npm run dev                      # 开发服务器
npm test                         # 单元测试（vitest）
npm run build                    # 类型检查 + 生产构建
npm run smoke                    # 有解/无解冒烟（退出码 0/1）
npm run verify:all               # 测试 + 构建 + 冒烟 一次跑完
```

## Docker / Compose（WEB_PORT 可配置）

```bash
# 启动站点（默认宿主端口 8080，可用环境变量覆盖）
WEB_PORT=9090 docker compose up --build -d
curl -f http://localhost:9090/        # 健康检查
docker compose ps                     # STATUS 应为 healthy

# 一次性认证服务：代码测试 → 构建 → 有解/无解冒烟，完成后以退出码结束
docker compose build verify
docker compose run --rm verify        # 全绿退出码 0；任一失败退出码非 0
```

- `web`：nginx 静态站点，容器监听端口由环境变量 `WEB_PORT` 控制（默认 8080），
  内置 `HEALTHCHECK`。
- `verify`：一次性服务（`restart: "no"`），执行
  `npm test && npm run build && npm run smoke` 后退出。

## 界面使用要点

- 节点：净注入为正＝氮气源，为负＝排放口，为 0＝中转展柜。
- 风道：`起点 → 终点` 即气流方向；下限填正数表示该风道必须维持最低换气量。
- **每次修改草稿，已认证的流量与结论立即失效**（顶部状态条变为“未认证 / 已失效”），
  需重新点击“执行认证”。认证结论只对按下按钮那一刻的草稿快照负责。
- 内置「可行示例」「无解示例」可一键载入对照。
