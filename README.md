# 封闭展柜氮气风道 · 整数流量认证

换气前，保管员需要确认氮气会沿**有向风道**送达各展柜、并能从排放口带走，
不留任何失去保护气氛的角落。本应用对一张可编辑的有向网络做
**带整数下界的可行性流认证**：

- **节点净注入量** `b[i]`：`>0` 向管网供气（氮气源），`<0` 抽气/排放，`0` 中转展柜；
- **风道方向与整数上下限**：每条有向风道 `u→v` 的流量必须为整数且 `lower ≤ f ≤ upper`；
- 认证同时裁决三件事：
  1. **全网净注入平衡**：`Σ b[i] = 0`；
  2. **节点收支守恒**：每个节点 `流出 − 流入 = b[i]`；
  3. **风道容量区间**：每条风道流量落在 `[lower, upper]`，**正下限同样参与整体裁决**。

每次修改草稿（节点、净注入量、风道方向或任一上下限），上一次的认证流量与结论
**立即失效**，需重新点击“运行认证”。

## 算法

经典带下界可行流变换：令 `f = lower + x`，强制全部下限后，节点剩余需求
`d[i] = b[i] + 流入下限 − 流出下限`；加超源 `S`（向 `d>0` 的节点送 `d`）和
超汇 `T`（`d<0` 的节点向其排 `−d`），用 Dinic 求整数最大流。
当且仅当 `Σb=0` 且超源弧全部饱和时可行，最大流直接给出**逐风道整数流量**。

不可行时，依据**最大流–最小割**给出保管员看得懂的证据：

- 缺口节点集合（残量网中超源可达的最小割片区）；
- **最小未满足流量**（缺口）= 超源总需求 − 最大流；
- 逐节点未满足量（合计恰为总缺口）；
- 片区缺口恒等式：
  - 供气侧 `Σ_R b + Σ跨入下限 − Σ跨出上限 = 缺口`；
  - 抽排侧（全网抽排大于供气时）`−Σ_X b + Σ跨出下限 − Σ跨入上限 = 缺口`。

## 本地开发

```bash
npm install
npm run dev      # 开发服务器
npm run test     # Vitest 单元测试
npm run build    # 类型检查 + 生产构建到 dist/
npm run smoke    # 有解 / 无解 / 不平衡 三个冒烟断言
```

## Docker / Compose

端口由环境变量 **`WEB_PORT`** 配置（默认 `8080`），容器内 nginx 监听端口、
暴露端口与健康检查全部使用它：

```bash
# 启动健康站点（含 /healthz）
WEB_PORT=8080 docker compose up -d --build web
curl -s http://127.0.0.1:8080/healthz   # => ok

# 一次性认证服务：测试 → 构建 → 有解/无解冒烟，以退出码结束
docker compose build verify
docker compose run --rm verify          # 全绿退出码 0，任一失败非 0
```

`verify` 为一次性服务（`restart: "no"`），对应 Dockerfile 的 `verify` 阶段，其
`CMD` 为 `npm run test && npm run build && npm run smoke`。

## 目录

- `src/core/dinic.ts` — 整数容量 Dinic 最大流；
- `src/core/flow.ts` — 下界变换、可行性裁决、最小割缺口诊断；
- `src/App.tsx` — 可编辑草稿、认证失效控制、有解流量与无解缺口展示；
- `tests/` — 单元测试（独立复核区间、整数性、守恒与缺口恒等式）；
- `scripts/smoke.ts` — 有解/无解冒烟；
- `docker/nginx/default.conf.template` — 由 `WEB_PORT` 渲染的 nginx 配置。
